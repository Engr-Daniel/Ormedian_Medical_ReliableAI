# TASK.md

## Purpose

This file is the repository's current-task control surface.

It should answer:

- What are we working on now?
- What is the next concrete deliverable?
- What has been completed?
- What should not be started yet?
- What evidence is required before a task is considered done?

This file is intentionally different from:

- `AGENTS.md` — standing instructions for agents and contributors,
- `memory.md` — durable project context and accumulated decisions,
- `README.md` — repository overview and navigation.

`TASK.md` should stay short, current, and action-oriented.

## Constraints

- Do not prematurely build later phases while the current unit is still open unless explicitly requested.
- Do not treat a result as scientific evidence without sufficient experimental context.
- Do not commit patient data, PHI, restricted medical datasets, credentials, or secrets.
- Keep research reasoning in `research-notes/` and execution evidence in `experiments/`.
- Prefer small, reviewable changes over broad repository rewrites.

## Update rule

Update this file whenever:

- the active unit changes,
- a major deliverable is completed,
- the next task changes,
- a blocker is discovered,
- a unit is formally closed.

Keep historical detail in the relevant curriculum, assessment, research-note, experiment, or mentor-review artifact rather than allowing `TASK.md` to become a long project diary.
